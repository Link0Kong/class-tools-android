# 「演示」（PPT 上传自动转换 + 分步播放）· Android 实现说明（2026-11-09）

> 契约唯一真源：`web/ppt/CONTRACT.md` v1（接口/字段/状态/播放语义）；
> 设计参考：`web/ppt/DESIGN.md`（竞品拆解、控制条/抽屉/热点规格、老设备预算）。
> 本文只记录 **Android 端**实现、与契约的对应关系、已知限制与验证证据。版本 **v3.3.0 / versionCode 9**。

## 1. 需求结论（与契约 §1 一致）

教室电脑老旧：PPT 动画多会卡死、嵌入视频换机就「媒体不可用」。方案＝上传端只传源文件，本机转换机一次性渲染成
**分步图片**（每页每个点击动画步一张）并把嵌入视频/音频转 H.264 MP4 / AAC；三端播放器只做「加载图片 + 切图 + 播 MP4」。

**已知取舍（如实说明，不掩饰）**：

- 分步图片优先保证内容完整 + 播放流畅；同一文本框内逐段文字出现的动画**合并为整段出现**；
  强调动画/运动路径**只取该步最终视觉状态**，不是逐帧动画；
- 播放器的 `tr` 转场（fade/push/wipe/zoom/cover）在 Android 端按「淡入」保守实现——`push` 额外 8% 横移，
  其余统一交叉淡入，低端机（≤2 核或 memoryClass≤2GB）强制 `fade 200ms`、步内直切（契约 §5 明确允许降级）；
- 转换机需开机在线（Windows + PowerPoint）；离线时列表提示「转换机离线 · 排队中」并继续排队，不报错；
- 转换产物与源文件在 OSS 公共读（URL 含 128bit 随机 deckId，不可枚举）；班级 PPT 视为班内公开材料。

## 3. 契约对应表

| 契约 | Android 实现 |
|---|---|
| §2 身份头 | 复用现有 `ApiClient`：`Authorization: Bearer <PUBLISHABLE_KEY>` + **`X-Class-Token: <token>`**（ARCHITECTURE §4 既有口径；服务端 `auth_hdr()` 同时接受 `X-Device-Id`/`X-Class-Token`，未改全局身份层） |
| §3.1 deck 表 | 建行字段：`id=d+base36(ms)+6 位随机`、`title`（≤80）、`owner_sid/owner_name`、`client="android"`、`status="uploading"`、`source_name/source_size/chunk_count`、`aspect="16:9"`、`created_at/updated_at`、`deleted=false` |
| §3.2 分片 | 512KiB/片（最后一片可小）；base64（`java.util.Base64`）；`Prefer: resolution=merge-duplicates,return=minimal`；并行 ≤4；进度＝已成功片数/总片数 |
| §3.4 心跳 | `GET site_assets?id=eq.ppt_agent&select=body,updated_at`；`now - seen_at > 180000` 判离线；列表轮询同一轮并行拉取 |

| §4.4 列表 | 只查浅字段（**不带 manifest**）、`deleted=eq.false&order=created_at.desc&limit=100`；别人 uploading 隐藏；本人进行中置顶 |
| §4.5 清单 | `select=manifest,title,slide_count,step_count,aspect,cover_url,source_name,source_key,converted_at&id=eq.<id>`；manifest 空 → 「还没转换完成」 |
| §4.6 软删/重试 | PATCH `deleted=true` / `status=queued,progress=0,error=""`；入口仅本人卡片（更多菜单/卡片内「重试」） |
| §4.7 轮询 | 列表页可见 10s（`repeatOnLifecycle(RESUMED)`，隐藏停止、回前台立即拉）；播放页不轮询 |

## 4. 交互实现要点（对齐 DESIGN.md）

### 4.1 列表页（DESIGN §4.1/§4.2）

- 卡片 96dp 横向：封面 128×72（圆角 8，`cover_url`，无则占位图标）+ 标题 15/600 单行省略 + 元信息「页数 · 上传者」+ 状态胶囊 22dp；
- 顶部「上传 PPT」主按钮（雾青实心）；点卡片就绪即进播放器（非就绪 toast 当前状态）；
- 上传：SAF `OpenDocument`（ppt/pptx MIME，附带 octet-stream 以兼容部分文件管理器，选中后按扩展名再校验）→
  立即读取文件名/大小（≤64MiB）→ 可选改标题（默认文件名去扩展名）→ 就地插入进度卡片（已成功片数百分比，可取消→软删）→
  完成自动变「排队转换」；失败：上传中断的卡片点「重试」= 重新选文件（源文件不在本机，契约 §4.2 要求重走分片），
  转换失败的卡片点「重试」= 云端重新排队（§4.6）；
- 本人卡片 `⋯` → 删除（二次确认，软删）；空态「还没有演示文件」+「上传 PPT」按钮 + 一句说明；骨架 3 张（首次加载）；
- 转换机离线且有排队任务 → 顶部横幅「转换机离线 · 任务排队中」；列表拉取失败 → 回退上次列表 +「离线：显示上次列表」。

### 4.2 播放器（DESIGN §4.3–§4.11）

| 项 | 实现 |
|---|---|
| 全屏 | `WindowInsetsController` 隐藏系统栏（`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`）+ `FLAG_KEEP_SCREEN_ON`；退出恢复 |
| 舞台 | 纯黑 `#000`，图片 `contain` letterbox（按 manifest `w/h` 计算显示区，热点用同一显示矩形换算） |
| 顶部 | 2px step 总进度条；左上文件名（随控制条淡出） |
| 控制条 | 底部 48dp 圆角 14 半透明条：‹ / `3 / 12` + 页内步点 / › / 分隔 / 缩略图 / 备注 / 黑屏 / ⋮（下载原件、退出演示）；3s 自动隐藏（触摸唤出，键盘/音量翻页不唤出） |
| 切换 | 单击右 2/3 下一步、左 1/3 上一步；左右滑动（阈值 max(40px, 屏宽 12%)）；键盘 →/←/Space/PageDown/PageUp/MoveHome/MoveEnd；**音量+ 前进 / 音量− 后退**（Activity 转发） |
| 步/页 | 后退粒度 step；step=0 退上页末步；跨页用 `tr` 转场、页内 150ms 淡入（低端 0）；步点仅当前页 step≥2 显示 |
| 缩略图 | 底部横向抽屉（`thumb`，无则首步图），点击跳页、当前页高亮；遮罩点击关闭 |
| 备注 | 底部抽屉（当前页 `notes`，空则「本页无备注」）；`S` 键切换 |
| 黑屏 | `B` 键 / 控制条按钮；任意触摸或按键恢复且不显示任何 UI |
| 媒体 | 视频 56dp 圆形播放键（音频 40dp 音符）+ 时长角标；**点击才播**；媒体层独立全屏（VideoView + MediaController，左上 ×）；播放结束/关闭回当前步；**不随 step 卸载，仅换页/退出销毁**；失败热点灰化「视频不可用」不阻塞翻页 |
| 图片 | 当前图片失败保留上一张 + 「图片加载失败 · 重试」；加载器失败自动重试 1 次 |
| 预加载 | 当前步后 2 张主图（当前最高优先级）；缩略图抽屉按需加载 |
| 退出 | 有进度且不在末页 → 「退出演示？」继续/退出；系统返回键优先级：媒体层 → 缩略图 → 备注 → 黑屏 → 退出确认 |
| 下载原件 | Android `DownloadManager` 写入系统「下载」目录（无需存储权限）；异常退回浏览器打开 |

## 5. 已知限制（如实记录）

1. **转场是保守实现**：仅淡入（push 轻横移），没有实现 wipe 裁切/zoom 缩放/cover 覆盖的逐帧效果——契约允许降级，课堂优先流畅。
2. **续播未做**：DESIGN §4.10 的 DataStore 续播（`deckId → (slide, step)` 7 天内「续播」）列为 P2，未实现；每次进播放器从第 1 页第 1 步开始。
3. **重命名未做**：列表 `⋯` 只有「删除」；契约 §3.1 标题可改，但三端均未提供改名入口（转换前标题在 Android 上传时可改）。
4. **残留 uploading 行**：上传中途杀进程会留下本人 `uploading` 行（列表显示「上传中」，可手动删除）。列表查询按契约固定浅字段、不带 `updated_at`，故未做「超时自动清理」。
5. **音量键翻页仅在播放器路由生效**；其他页面音量键仍是系统音量（符合预期）。
6. **音频热点**用 VideoView 播放 m4a（黑底 + 「音频播放中」），控制为系统 MediaController，未做自定义音频 UI。
7. **推送/轮询边界**：列表 10s 轮询在后台/锁屏停止（LIFECYCLE 感知），后台不会更新任务状态；回到前台立即强拉。
8. **端到端真实转换依赖本机转换机与管理员 token**：Android 侧单元/构建/预览已验，真实「上传→转换→播放」链路由 Lead 用测试身份执行（契约 §9.3）。
9. 图片解码宽度默认 1280（缩略图 400），LRU 常驻上限 = 堆/8（8–64MB）；极低端机若 OOM 可再降。
10. 未新增任何依赖；`VideoView` 对 H.264/AAC 的兼容性由系统解码器决定（契约要求转换机统一转 H.264/AAC）。

## 7. v1.2 增量（2026-11-10）：原样播放高保真视频模式

> 契约 §11；本文 v1.1 部分描述的分步播放器行为保留不变。v1.2 详细实现/契约对应/OSS 域名与下载限制见
> **[docs/PPT_VIDEO_20261110.md](PPT_VIDEO_20261110.md)**。
